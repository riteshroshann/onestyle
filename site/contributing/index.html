Small, finished, tested and plain. The same bar applies to everyone, including the people who started it.

The bar

  1. Finished. No placeholders, no TODOs, no stubs. If something cannot be finished, leave it out and say what is missing.
  2. Verified. Run it, test it, look at it. Screenshots at 390 and 1440 pixels for anything visual, in both the light pages and the dark Talk page.
  3. Small. One change per pull request, matching the code around it. Comments say why, not what.
  4. Honest. Fix the cause of a failure; never weaken a test to make it pass. Every number you add must be reproducible.

Before you open a pull request

cd web
bun x tsc --noEmit -p .           # types
bun run build                     # the static export must build
bun tests/assistant.test.ts       # Ask, retrieval and guardrails
cd ../engine && pytest            # the engine, if you touched it

Design rules

White, Google Sans at weight 500 for display type, one accent (#38bdf8), glass only on what floats, generous space. No badges, check-mark lists, emoji icons, nested cards or decorative gradients. Every state is designed: hover, focus, pressed, disabled, loading, empty and error. Motion answers a person's action, and reduced-motion turns it off.

Writing

Copy in plain, active, sentence-case words. Buttons say what happens: Send to a maker, not Submit. Commit messages are short and plain, describing what changed in one line.

Data and safety

Never log what people type. Keep secrets out of code; they live in the deployment's environment. New tables get row-level security before they get data. The Ask guardrails, retrieval threshold and output checks are tested; keep them that way.
